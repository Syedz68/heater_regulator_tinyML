# Simulated price-aware heater controller

CPU-only prototype for a future Raspberry Pi 3B controller. **It does not use GPIO, read physical sensors, or switch a real heater. Every heater action, indoor response, energy figure, and comparison result is simulated. Never connect a mains heater directly to Raspberry Pi GPIO.**

The project compares a static 19–21 °C hysteresis thermostat, a simple price-aware rule, and an MLP-based price-aware controller. The MLP predicts indoor temperature one hour ahead from current indoor temperature, outdoor temperature, and simulated heater duty for the upcoming hour. Electricity price is used only by controllers when choosing duty; it is not a thermal-model feature.

## Layout

- `heater_controller/data.py`: CSV parsing, UTC/hourly alignment, DST/gap handling, and price conversion.
- `heater_controller/thermal.py`: one-zone simulator and simulated-duty training generator.
- `heater_controller/training.py`: chronological split, CPU MLP, metrics, persistence baseline, and artifacts.
- `heater_controller/controllers.py`: all three policies.
- `heater_controller/evaluation.py`: shared-scenario energy, cost, comfort, and switching metrics.
- `scripts/`: preparation, simulation, training, and comparison commands.
- `tests/`: focused timestamp, split, accounting, and comfort tests.
- `datas/`: unchanged source exports.

## Setup and exact local CPU workflow

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

python -m scripts.prepare_data \
  --smhi datas/temperatureData.csv \
  --prices datas/pricedataSweden.csv \
  --output artifacts/hourly_profile.csv

python -m scripts.generate_training_data \
  artifacts/hourly_profile.csv \
  --output artifacts/simulated_training.csv

python -m scripts.train_mlp \
  artifacts/simulated_training.csv \
  --model artifacts/heater_mlp.joblib \
  --predictions artifacts/test_predictions.csv

python -m scripts.compare_controllers \
  artifacts/hourly_profile.csv artifacts/heater_mlp.joblib \
  --heater-power-kw 2.0 \
  --output-dir artifacts/evaluation

python -m pytest -q
```

Training uses `StandardScaler` followed by `MLPRegressor(hidden_layer_sizes=(8, 4), activation="relu")`, on CPU. Rows stay time ordered: 70% train, 15% validation, and 15% test. Output includes validation/test MAE and RMSE, a test persistence baseline, a joblib model, and test predictions CSV.

## Configurable canonical CSV input

Instead of the repository-specific adapters, provide a CSV containing:

| Column | Meaning | Required |
|---|---|---|
| `timestamp` | ISO-8601 timestamp; offsets strongly recommended | yes |
| `outdoor_temp` | outdoor temperature, °C | yes |
| `price` | SE3 spot price in the unit passed by `--price-unit` | yes |
| `indoor_temp` | measured/sourced indoor temperature, °C | optional |

```bash
python -m scripts.prepare_data --input input.csv \
  --timezone Europe/Stockholm --price-unit SEK/MWh \
  --output artifacts/hourly_profile.csv
```

Supported price units: `EUR/MWh`, `EUR-MWh`, `EUR/kWh`, `SEK/MWh`, and `SEK/kWh`; output is per kWh in the same currency. Aware timestamps are converted to UTC before hourly resampling. Naive timestamps use the configured zone; spring-forward nonexistent times shift forward, while ambiguous fall-back data must include offsets or form an inferable ordered sequence. Duplicate instants are averaged, short gaps up to three hours are interpolated, and unresolved required rows are removed.

## Provenance, assumptions, and limitations

`datas/temperature2010/*.T15.txt` is SML2010 data. It may inform indoor-temperature patterns only. Its motor-state columns are **not verified electric-heater duty and are never treated as heater state here**. SML2010 and Swedish SMHI weather remain distinct sources; this project does not present a combination as measurements from a Swedish home.

The initial model learns from heater duties and responses generated by the thermal simulator. A predictor needs simulated or measured heater-duty examples to learn heating response. The simulator is deliberately simple: one mixed zone, fixed heat loss/heating gain, hourly steps, and no occupancy, solar gain, wind, humidity, detailed thermal mass, or equipment dynamics. Calibrate `ThermalParameters` before any real-world use.

Energy is `heater power (kW) × duty × 1 hour`. Cost is energy times converted SE3 spot price per kWh. **Reported cost is spot-price-only and excludes taxes, grid/network charges, retailer fees, and currency conversion.** Comfort reporting includes hours and degree-hours outside 19–21 °C. A switch is a transition between zero and nonzero duty.

All controllers start at the same temperature and use the same hourly weather, prices, heater rating, and deterministic simulator. Results are simulations, not evidence of savings in a real building.
